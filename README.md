# Квитто — API платежей на FastAPI

Тестовое задание на позицию **Junior Python Developer (FastAPI)**.

Сервис моделирует приём оплаты курсов онлайн-школы: показывает тарифы, рассчитывает стоимость с промокодом и график рассрочки, создаёт платежи и принимает подписанные уведомления банка об изменении статуса. **Реальных списаний денег и интеграции с банком нет.**

## Стек

- **Python 3.12, FastAPI, Pydantic v2** — API и валидация.
- **PostgreSQL 17, SQLAlchemy Async, asyncpg** — хранение данных.
- **Alembic** — миграции.
- **pytest, pytest-asyncio, HTTPX, Testcontainers** — тестирование.
- **Ruff, GitHub Actions** — проверка кода и CI.
- **Docker Compose, uv** — запуск и управление зависимостями.

## Возможности

| Функция          | Поведение                                                                                                |
| ---------------- | -------------------------------------------------------------------------------------------------------- |
| Тарифы           | `basic` — 9 900 ₽, `standard` — 19 900 ₽, `premium` — 29 900 ₽; недостающие тарифы создаются при запуске |
| Денежные расчёты | Все суммы в API и БД хранятся **целыми копейками**, без `float`                                          |
| Промокод         | `KVITTO10` — скидка 10%, без учёта регистра; неизвестный код — `422`                                     |
| Оплата           | `card`, `sbp`, `installment`                                                                             |
| Рассрочка        | На 3, 6 или 12 месяцев; остаток от деления распределяется в первые платежи                               |
| Идемпотентность  | Повторный запрос с тем же `Idempotency-Key` возвращает существующий платёж                               |
| Вебхук банка     | Проверка подписи `X-Signature` по HMAC-SHA256                                                            |
| Статусы          | Только разрешённые переходы; запрещённый переход — `409`                                                 |
| Список платежей  | Фильтрация по `email` и `status`                                                                         |

Пример распределения **1 990 000 копеек** на три месяца: `[663334, 663333, 663333]`. Сумма графика всегда равна сумме к оплате.

Для `installment` поле `installment_months` обязательно. Для `card` и `sbp` срок не задаётся; `installment_months` и `schedule` в ответе равны `null`.

### Статусы

```text
pending ──► succeeded ──► refunded
   └──────► failed
```

Новый платёж получает статус `pending`. Любой другой переход, в том числе повторное установление текущего статуса, возвращает `409` и `{"error":"invalid_transition"}`. Состояние платежа при этом не изменяется.

### Надёжность обработки

- **Идемпотентность:** уникальное ограничение на ключ платежа в PostgreSQL не позволяет создать дубль. При повторе существующего ключа с валидным телом API возвращает тот же платёж с кодом `200`, а не создаёт новый. Тело повторного запроса с первоначальным не сравнивается.
- **Конкурентные вебхуки:** при изменении статуса используется блокировка строки `SELECT FOR UPDATE` и проверка допустимого перехода внутри транзакции.
- **Подпись вебхука:** HMAC-SHA256 вычисляется по **исходным байтам HTTP-тела** с ключом `WEBHOOK_SECRET`. Отсутствующая или неверная подпись — `401`.

## API

Все маршруты имеют префикс `/api/v1`. Интерактивная документация: [Swagger UI](http://127.0.0.1:8000/docs).

| Метод  | Маршрут                         | Назначение                                        |
| ------ | ------------------------------- | ------------------------------------------------- |
| `GET`  | `/api/v1/tariffs`               | Список тарифов                                    |
| `POST` | `/api/v1/payments`              | Создание платежа (`201`), повтор по ключу (`200`) |
| `GET`  | `/api/v1/payments/{payment_id}` | Получение платежа по UUID (`404`, если не найден) |
| `GET`  | `/api/v1/payments`              | Список платежей с фильтрами `email`, `status`     |
| `POST` | `/api/v1/webhooks/bank`         | Смена статуса платежа по подписанному уведомлению |

Некорректные входные данные и неизвестный тариф возвращают `422` в стандартном формате валидации FastAPI.

## Запуск через Docker Compose

**Требования:** Git, Docker и Docker Compose v2; свободные порты `8000` и `5433`. На Windows необходим работающий Docker Desktop с Linux-контейнерами. Локальная установка Python для этого способа не нужна.

### 1. Клонировать проект

```bash
git clone https://github.com/DanilZheltikov/test-kvitto-payment-api.git
cd test-kvitto-payment-api
```

### 2. Создать `.env`

Создайте файл `.env` и заполните его по образцу [.env.example](./.env.example).

Задайте пароль PostgreSQL и непустой `WEBHOOK_SECRET`. При запуске через Compose используйте `DB_HOST=postgres` и `DB_PORT=5432`.

| Переменная           | Назначение                               |
| -------------------- | ---------------------------------------- |
| `POSTGRES_DB`        | Имя базы                                 |
| `POSTGRES_USER`      | Пользователь PostgreSQL                  |
| `POSTGRES_PASSWORD`  | Пароль PostgreSQL                        |
| `DB_HOST`, `DB_PORT` | Адрес БД: `postgres:5432` внутри Compose |
| `WEBHOOK_SECRET`     | Секрет для проверки HMAC-подписи         |

Значения из примера предназначены для локальной разработки.

### 3. Запустить сервис

```bash
docker compose up --build -d
```

Compose поднимает **PostgreSQL**, запускает отдельный контейнер **`migrate`** для `alembic upgrade head`, а после успешной миграции — **`api`**. При первом старте приложение добавляет тарифы `basic`, `standard` и `premium`.

**Адреса:**

- Swagger UI — <http://127.0.0.1:8000/docs>
- OpenAPI — <http://127.0.0.1:8000/openapi.json>
- Список тарифов — <http://127.0.0.1:8000/api/v1/tariffs>
- PostgreSQL с компьютера — `localhost:5433`

## Примеры запросов

Примеры `curl` рассчитаны на Bash / Git Bash. Для ручной проверки также можно использовать Swagger UI.

### Получить тарифы

```bash
curl http://127.0.0.1:8000/api/v1/tariffs
```

Скопируйте фактический `id` тарифа `standard` из ответа и используйте его в следующем запросе: **ID не гарантированно равен `1`**.

### Создать платёж

```bash
curl -i -X POST http://127.0.0.1:8000/api/v1/payments \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: order-123' \
  -d '{
    "tariff_id": 1,
    "email": "student@example.com",
    "method": "installment",
    "installment_months": 3,
    "promo_code": "kvitto10"
  }'
```

Замените `tariff_id` на ID из ответа `/tariffs`. Для тарифа `standard` результат расчёта будет таким (фрагмент ответа):

```json
{
  "status": "pending",
  "amount": 1791000,
  "discount": 199000,
  "schedule": [597000, 597000, 597000]
}
```

Полный ответ также содержит `id`, `tariff_id`, `method`, `installment_months`, `email`, `created_at`. Первый запрос возвращает **`201 Created`**, повтор с тем же непустым `Idempotency-Key` и валидным телом — **`200 OK`** и существующий платёж. Без ключа каждый POST создаёт новый платёж; пустой ключ возвращает `422`.

### Получить платёж и отфильтровать список

Подставьте UUID из ответа на создание платежа:

```bash
curl http://127.0.0.1:8000/api/v1/payments/REPLACE_WITH_PAYMENT_UUID
curl 'http://127.0.0.1:8000/api/v1/payments?email=student%40example.com&status=pending'
```

Оба фильтра необязательны. Если указаны оба, платёж должен соответствовать обоим условиям. Без фильтров возвращаются все платежи, при отсутствии совпадений — пустой список.

### Отправить подписанный банковский вебхук

Маршрут: `POST /api/v1/webhooks/bank`. Тело:

```json
{
  "payment_id": "REPLACE_WITH_PAYMENT_UUID",
  "status": "succeeded"
}
```

Нужен заголовок `X-Signature`: hex-представление HMAC-SHA256 от отправляемых байтов JSON с ключом `WEBHOOK_SECRET`. После подписания тело нельзя менять, включая пробелы и переводы строк.

## Тестирование и качество кода

Для локального запуска тестов нужны **Python 3.12, uv и Docker** (Docker должен быть запущен; само приложение запускать не требуется).

#### Установка зависимостей:
```bash
uv sync --locked --dev --python 3.12
```
#### Запуск pytest:
```bash
uv run --no-sync pytest -v
```
#### Запуск линтера:
```bash
uv run --no-sync ruff check .
```

Интеграционные тесты используют **Testcontainers**: поднимают отдельный PostgreSQL 17 и применяют Alembic-миграции. Рабочая база не затрагивается, локальный `.env` для тестов не нужен. При первом запуске Docker может скачать необходимые образы.

Проверяются расчёты сумм и рассрочки, промокод, тарифы, создание и получение платежей, идемпотентность, конкурентные запросы, разрешённые и запрещённые переходы статусов, подпись и валидация вебхука, фильтрация платежей.

**Денежные unit-тесты можно запустить отдельно без Docker:**

```bash
uv run --no-sync pytest tests/test_money.py -q
```

Настройки линтера находятся в [pyproject.toml](./pyproject.toml). 

**CI:** [GitHub Actions](./.github/workflows/main.yml) запускает Ruff и pytest на каждый `push` и `pull_request`. База для тестов создаётся через Testcontainers. Деплой не выполняется.
